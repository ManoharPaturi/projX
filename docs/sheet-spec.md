# The OMR sheet spec — format and physics

`packages/omr_spec` is the single source of truth for every sheet layout. A
spec is authored **once, in millimetres**, and compiled to both of its
consumers:

```
                 ┌────────────────────┐
 SheetSpec (mm) ─┤ compileSheetPdf     ├──▶ printable vector PDF
                 │ compileDetection…  ├──▶ DetectionTemplate (8 px/mm canvas)
                 └────────────────────┘
```

Neither the PDF nor the template is ever edited by hand. Both take page
geometry (fiducial centres, QR rect, timing bars) from the same
`LayoutGeometry` class, so **template-vs-print drift is impossible by
construction** — the property that kills the classic silent killer of OMR
systems (sheet printed from one layout, bubbles read from another).

## Identity and immutability

| Concept | Rule |
|---|---|
| `layoutId` | Human identity (`std90`, `neet180`). Immutable once printed. |
| `layoutVersion` | Bumped by **any geometric change**. Colours and instruction text are exempt. |
| `specHash` | `sha256(canonicalJson(spec))` — stored with the layout row, re-verified on load. A stale template refuses to load. |
| QR payload | `OMR1:<layoutId>:v<layoutVersion>`, ECC M, ≥15 mm. The QR is authoritative: detection never guesses which template to apply. |

A sheet printed in 2026 still grades correctly in 2030 because the QR on the
paper resolves the exact immutable version it was printed from.

## Authoring model — additive geometry, no per-bubble coordinates

A `FieldBlock` is generated by pure addition from an origin plus two pitches:

```
origin (mm)  ── centre of the FIRST bubble
bubblePitch  ── centre-to-centre along the OPTION axis
rowPitch     ── centre-to-centre along the FIELD axis
direction    ── vertical: questions stack down, options run right (MCQ rows)
               horizontal: digit columns advance right, 0–9 stack down (grids)
fieldLabels  ── range-expandable: ['q1..q30'] → q1…q30, ['roll1..roll8'], ['set']
```

Block **extent is computed** (`pitch × (count−1) + bubble`), never stored —
and `validateSheetSpec` rejects any extent that overflows the content rect.
This is what makes the format typo-resistant: a wrong pitch or origin is a
loud validation error with the actual mm numbers, not a silently mis-printed
sheet. (The check exists because this exact class of mistake — 45 rows on a
landscape A4 that doesn't have the height — was made during design and caught
by arithmetic.)

Field labels are **globally unique** across the whole sheet and become the
database join keys (`bubble_reads.fieldKey`): `q1…q180`, `roll1…roll8` (the
8th column is the checksum digit), `set`.

## Layout physics (enforced at build and load)

| Rule | Limit | Why |
|---|---|---|
| Margin | ≥ 10 mm all sides | Printable area on cheap laser/inkjet |
| Bubble size | 3–6 mm major axis | Below 3 mm phone photos can't segment; above 6 mm sheets get sparse |
| Pitch | ≥ 1.4 × major axis | Filled marks must never straddle neighbouring ROIs |
| Stroke | 0.15–0.35 mm | Thick outlines photocopy into false FILLED |
| Fiducial | 6–12 mm, ~2.5–3 × bubble, ≥3 mm white surround, ≥5 mm from paper edge | Unambiguous template match; survive 2 photocopy generations |
| QR | ≥ 15 mm, ECC M | Phone-readable module size |
| Timing bar | height < row pitch | Bars must stay separate blobs |
| Shared row grid | all MCQ blocks share `rowPitchMm` and origin y | One timing bar covers every column; the track is DERIVED from the first MCQ block's grid and cannot drift from it |

## Ink discipline

| Element | Colour | Read by detection? |
|---|---|---|
| Bubble outlines, option letters, question numbers, block captions | drop-out orange `#D64000` | No — detection reads the channel where this ink is weakest |
| Fiducials, timing bars, QR | black | Yes — registration only |
| Header title, instructions, serial | black | No — outside content |

## Registration design

- **Three identical squares** (tl, tr, br) + **one distinct L anchor** (bl).
  The odd one out makes orientation unambiguous after the perspective warp,
  and doubles as the fallback anchor when a square is occluded or glazed.
- **Timing track** down the left edge: one black bar per row band. Corner
  fiducials fix a 4-point homography, but a page curved on a desk bends rows
  several mm mid-sheet where a homography cannot follow. The bars give (a)
  per-row index recovery, (b) a curvature residual measurement that routes
  curled sheets to review instead of mis-grading them, and (c) a
  least-squares affine fallback when corner matching fails.

## Presets (built, never hand-authored — `builders/jee_style_sheet.dart`)

| Preset | Layout | Geometry | Capture floor |
|---|---|---|---|
| **A `std90`** | 3 × 30 questions + roll8 + set | 5.0×3.5 mm ovals, 7.6/7.8 mm pitch | 11.4 px/mm → ~2400 px across the sheet |
| **B `neet180`** | 4 × 45 questions + roll8 + set | 4.0×3.0 mm ovals, 5.7 mm pitch | 13.3 px/mm → ~2800 px across the sheet |

Both fit portrait A4 inside the margins; the validator proves it on every
build (see `packages/omr_spec/test/`).

## Detection canvas

`PX_PER_MM = 8.0` → portrait A4 becomes **1680 × 2376 px**; Preset A's bubble
major axis is exactly **40 px** — OMRChecker's proven working size. The
reader samples the inner **70 %** of each bubble (excluding the printed
stroke) and classifies EMPTY / PROBABLE / FILLED with two-tier largest-gap
thresholding; PROBABLEs route to the human review queue.

## Using it

```bash
dart run tools/omr_cli pdf      --preset A --out build/std90.pdf
dart run tools/omr_cli template --preset A --summary
dart run tools/omr_cli spec     --preset A --hash
```

```dart
import 'package:omr_spec/omr_spec.dart';

final spec = buildStandard90();                 // already validated
final pdf  = await compileSheetPdf(spec);       // Uint8List
final t    = compileDetectionTemplate(spec);    // bubbles, fiducials, timing bars
final hash = specSha256(spec);                  // store with the layout row
```
